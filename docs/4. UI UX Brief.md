# 4. UI/UX Brief

## Design principles and visual direction

The product is a professional audit tool. It should feel calm, dense where needed and trustworthy, closer to a code-review or security console than a marketing site.

- **Evidence first.** Nothing is claimed without a code snippet, file path and line range on the same screen.
- **Show the math.** Every risk number opens to its factors.
- **Status is never ambiguous.** Finding state, verification and review state each have a distinct label and color.
- **Uncertainty is visible.** "Insufficient evidence" and "unresolved" get their own treatment, not a muted pass.
- **Safe by default.** Secrets are always masked in the UI.

**Visual direction**

| Element | Direction |
| --- | --- |
| Theme | Light and dark, follows system setting |
| Layout | Left sidebar navigation, wide content area, split panes for finding detail |
| Typography | Clean sans-serif for UI; monospace for code, paths and hashes |
| Color | Neutral base. Severity scale: critical (red), high (orange), medium (yellow), low (blue), info (gray). Status colors are separate from severity colors |
| Density | Compact tables with sortable columns and saved filters |
| Motion | Minimal; progress bars and a subtle live indicator only |

## Screen specifications

**1. Login.** Email, password, error message, no signup in v1 (admin creates users).

**2. Dashboard.** Cards: audits running, awaiting review, completed this week, total cost. Table of recent audits with repository, status, overall risk, date.

**3. Repositories and upload.** Drag-and-drop zip or Git URL field; client-side size check; list of repositories with last audit result; "Start audit" button.

**4. Audit progress.** Horizontal stage tracker (Intake, Index, Scanners, Agents, Validation, Risk, Review, Report) with live state per stage, elapsed time, running cost, and a log of events. Failed stages show a retry note, not a blank.

**5. Findings list.** Left filter rail (category, severity, status, verification, file path search). Table columns: title, category, severity, confidence, status, file:line. Row click opens detail in a right pane.

**6. Finding detail.** Header with title and badges. Code viewer with highlighted line range and surrounding context. Panels: evidence, reasoning, business impact, recommendation, related files retrieved by the agent, history of status changes.

**7. Risk breakdown.** Overall level with the rule that set it (for example, severity floor), then a table of findings with severity weight, confidence, exposure multiplier and resulting score. Separate card: "Technical severity" versus "Business risk: needs information outside the repository".

**8. Review queue and review detail.** Queue lists critical-risk audits with age. Detail shows original findings, evidence, scores, aggregation rationale, then a decision form: Approve, Override (reason required, new level), Request more evidence (note required). Submit is disabled until the reason is filled.

**9. Executive report.** Summary paragraph, risk level, top findings, category breakdown, remediation priorities, limitations (what could not be assessed), reviewer decision block. Buttons: download PDF.

**10. Audit log.** Append-only table: time, user, action, object, before and after values. Read-only.

**11. Benchmark results (admin).** Table of runs by configuration (scanners only, single agent, multi-agent, multi-agent plus validation) with precision, recall, false positives, evidence accuracy, cost, runtime. Compare view for two runs.

**12. Settings (admin).** Users and roles, per-audit cost budget, model routing, retention period.

## Components, states and accessibility

**Reusable components**

| Component | Notes |
| --- | --- |
| SeverityBadge | Five levels, color plus text label |
| StatusBadge | scanner-confirmed, AI-suggested, verified, rejected, unresolved |
| VerdictBadge | Includes "insufficient evidence" |
| CodeViewer | Read-only, line highlighting, secret masking, copy path |
| StageTracker | Pending, running, done, failed, skipped |
| ScoreBreakdown | Expandable factors for each score |
| ReviewForm | Decision radio, reason textarea, validation |
| FilterRail | Multi-select filters with counts, URL-synced |
| DataTable | Sort, paginate, column toggle, empty and loading states |
| EventLog | Live SSE feed with auto-scroll toggle |

**States every screen handles:** loading (skeletons), empty (explains what to do next), error (reason plus retry), partial results (labeled incomplete), permission denied.

**Accessibility.** Keyboard navigable tables and panes; severity and status never conveyed by color alone; visible focus rings; WCAG AA contrast in both themes; semantic headings; live region for progress updates.

**Copy tone.** Plain and precise. Say "Insufficient evidence to assess license compliance", not "All good".

## Frontend technical notes

- React + TypeScript with Vite; React Router for routes; TanStack Query for server state.
- Generate TypeScript types from the FastAPI OpenAPI schema so the UI and API never drift.
- Use the browser `EventSource` API for the SSE progress stream.
- Store the JWT in memory plus a refresh cookie; role-based route guards.
- A component library such as shadcn/ui with Tailwind is a reasonable default; any equivalent works.
- Monaco or a lightweight syntax highlighter for the code viewer, read-only.
